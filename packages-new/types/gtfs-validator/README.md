# @tmlmobilidade/go-types-gtfs-validator

Types and helpers shared by the GTFS validator, the Core API, the Core frontend and the validator worker.

## Validation rules

The Go validator generates only `src/rules-new/rule-ids.ts` directly from its Go configuration fields. This file exports the sorted `GtfsValidatorRuleIdValues` list, the case-normalizing `GtfsValidatorRuleIdSchema` Zod schema, and the inferred `GtfsValidatorRuleId` type. Parser diagnostics and shared output IDs are excluded.

Do not edit this file by hand. Other rule schemas are maintained in TypeScript. The existing `src/rules/` contracts remain available for current consumers, but are no longer regenerated or checked by these commands.

```sh
npm run repo:validator-rules        # regenerate (requires Go)
npm run repo:validator-rules:check  # fail if rule-ids.ts is missing or stale
```

Package and Docker builds use the committed files and do not need Go. CI runs the check and the Go rule tests on pull requests and on pushes to `prd`.

### Exports

| Export | What it is |
| --- | --- |
| `GtfsValidatorRuleIdValues`, `GtfsValidatorRuleIdSchema`, `GtfsValidatorRuleId` | Generated rule IDs, runtime schema and inferred type. |
| `ruleSeverities`, `RuleSeverity` | Every severity the validator accepts. |
| `ruleGroups`, `RuleGroup` | The file sections of the rules, such as `agency` or `stops`. |
| `ruleConfigKeys`, `RuleConfigKey<G>` | The keys stored in each section. |
| `ruleIds`, `RuleId` | Agency rule catalogue IDs, excluding parser diagnostics. |
| `RuleOutputId` | Message IDs emitted by catalogue rules, including shared output IDs. |
| `ValidationRules`, `AgencyRules`, `RuleConfig`, ... | Complete configuration with defaults for optional rule settings. |
| `ValidationRulesInput`, `AgencyRulesInput`, `RuleConfigInput`, ... | Editable agency settings, which may be incomplete until configured. |
| `ruleCatalogue`, `RuleCatalogueEntry` | Editor metadata: editable rules and fixed technical notices. |
| `getRuleSeverity`, `setRuleSeverity` | Read and change one catalogue entry's severity in saved rules. |
| `getRuleConfig`, `setRuleConfig` | Read a rule's configuration and change its optional `options` or `compare` settings while preserving severity and metadata. Setting a field to `null` removes it. |
| `getSavedRuleSeverity` | The stored severity, or `undefined` when the rule was never configured. |
| `normalizeValidationRules` | Parse and check saved rules against the editor's policy. |
| `isRuleSeverity`, `parseRuleSeverity` | Runtime severity checks. |

The legacy configuration types are compile-time only. `normalizeValidationRules` removes saved rules whose group/key is no longer in the legacy configuration, while preserving `_file` settings and the options and metadata of retained rules. Missing rules stay absent so the Go validator can report them. A retained rule must have a valid severity. The editor passes `{ allowIncomplete: true }` to display rules with missing or invalid severities for correction; saving still uses the default validation.

Parser diagnostics remain runtime errors. They are excluded from the catalogue and generated rule IDs because they are not stored in agency validation settings.

The Go validator reads a flat rule-ID map, optionally wrapped in `validation_rules`. For example, `{"agency_id_unique":{"severity":"warning"}}` configures that rule directly; there is no `agency` section or `agency.` lookup prefix. Omitted rules default to `ignore`. Grouped file sections are rejected. File-presence settings use `<file>_file_missing` entries instead of `_file` inside a section. The older grouped TypeScript exports above describe legacy editor data, not the current Go input contract.

A stored config key can differ from the emitted rule id. For example, `frequencies.trip_id` emits `frequencies_trip_id_foreign`. Catalogue entries carry both `config_key` and `id`, and `setRuleSeverity` always writes under `config_key`.

### Rule dependencies

The validator uses only the `depends_on` arrays in the supplied rules JSON. Missing or empty arrays mean no prerequisites. There is no static dependency file in the Go binary. The legacy TypeScript catalogue is retained for existing consumers and is not the runtime dependency source.

Rules may depend on the synthetic `<section>_file_present` node. This tests whether the file was imported, independently of the agency's `_file` severity. Compound rules depend on the checks whose results they need; file availability is inherited transitively:

```text
agency_file_present
  ├─ agency_id_unique ────┐
  └─ agency_name_present ┴─ agency_id_matched_with_agency_name
```

Agency settings define `depends_on` edges using rule IDs from the same section, or that section's file-presence node. Unknown dependencies and cycles are rejected before validation. Grouped checks declare their execution scope (`trip`, `pattern`, `shape`, or `route`) on the Go configuration fields; a row check cannot depend on a later grouped check, and dependencies between different group scopes are rejected.

The shared runner sorts the DAG once per file and evaluates it independently for each row. Warnings and errors both fail a prerequisite. Ignored, unavailable, or blocked rules are skipped, and their dependents are skipped too. Independent rules and rows continue. Group checks use only the prerequisite outcomes of their own members, preserving the original source row numbers. Missing-file errors are reported without stopping validation of other available files.

A missing implementation never counts as a passed prerequisite. Technical parsing notices remain fixed and outside the configurable rule DAG.

### Removed exports

These exports from earlier releases were removed. There are no compatibility wrappers.

| Removed | Replacement |
| --- | --- |
| `gtfsValidationRulesConfig` | No replacement. Its defaults were not the validator's. Missing rules default to `ignore` in Go. |
| `GtfsValidationRuleSchema`, `GtfsValidationRule` | `ValidationRulesInput` for types, `normalizeValidationRules` for runtime checks. |
| `GtfsValidationRuleCompareSchema` | `RuleCompare` and `RuleCompareInput`. |
