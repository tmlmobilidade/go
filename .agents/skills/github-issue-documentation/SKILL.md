# Create documentation issue tickets

Use the shared process in [github-issues](../github-issues/references/workflow.md) and the [field catalog](../github-issues/references/issue-fields.md). This skill means the user has selected Documentation; if not, use the `github-issues` dispatcher first.

Identify the intended audience, the information they cannot find or trust, the authoritative behavior to document, and where readers expect to find it. Verify behavior from source or current docs before stating it as fact. Make acceptance criteria describe what a reader can discover or do after the change. Split only if sections or audiences can be documented and reviewed independently.
